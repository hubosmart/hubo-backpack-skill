# 03 Schematic

Pass `schematicPath` explicitly on every call to a **schematic tool**.

## Common tools

| Operation | Tools |
|---|---|
| Add | `add_schematic_component`, `batch_add_and_connect`, `add_schematic_wire`, `add_schematic_net_label` |
| Delete | `delete_schematic_component`, `delete_schematic_net_label` |
| Modify | `edit_schematic_component` / `batch_edit_schematic_components` (value, footprint, custom properties such as `{"properties": {"LCSC": "C4190"}}`) |
| Query | `list_schematic_components`, `get_schematic_pin_locations`, `get_net_connections`, `get_schematic_view_region` (render a region to check the layout) |
| Layout checks | `find_overlapping_elements`, `find_wires_crossing_symbols` |

## Generate parameters from data and check pin by pin

- **MCP parameters must be generated by script from a data file (the wiring table), never typed by hand.** A real incident: the pin net direction of one capacitor was typed backwards; while fixing it, `batch_connect(replace=true)` turned out **not to delete the old global labels**, shorting GND and +5V into one net.
- After every schematic change: export the netlist with `kicad-cli sch export netlist --format kicadxml`, compare it with the wiring table **pin by pin**, then run ERC (0 violations).
- `connect_to_net` also modifies the pad nets of the **loaded PCB** as a side effect. Before changing the schematic, make sure the MCP session has not loaded the production board.
- There is no tool to set DNP or `in_bom`; edit the schematic text directly: `(dnp yes)` / `(in_bom no)`.

## Schematic-to-PCB association: do not use `sync_schematic_to_board`

Measured to go wrong even on a **single-sheet schematic**: the canonical net name of a root-sheet local label carries a `/` (such as `/RF_ANT`) while sync writes it without, so parity reports `net_conflict`; it changes only pad nets, **not traces or copper pours**; it does not sync component values; and it reports "save refused" although the file was actually written.

**Alternative**: take the netlist exported by `kicad-cli` as the only source of truth, write pad nets with a pcbnew script by (reference designator, pad number), and apply the "old net → new net" mapping one-to-one to traces, vias and copper pours; or press F8 in the KiCad UI. Afterwards `--schematic-parity` must be 0.

**Keep net names stable**: use **global labels** (without `/`) for signal nets and power symbols for power. Switching to local labels puts a `/` prefix on all net names, and the PCB, custom DRC rules and net classes must all be changed accordingly. In KiCad 10 the net name of a power symbol comes from its Value field; when you need a power name that is not in the library (such as `3V3`), create a power symbol in the project library instead of faking it by editing the Value of `+3V3`.

## The schematic must be readable (layout rules)

| Requirement | Description |
|---|---|
| Arrange by function block | Add a title to each block; **draw wires inside a block** and use labels only between blocks. A drawing that relies on labels alone without wires looks to others like "incomplete nets" |
| Labels do not sit on wires | Attach global labels to a wire end or a short stub. If attached mid-wire, the wire runs through the label text |
| Junctions | Always draw a junction on T-connections (including a power symbol or label attached at a wire corner) |
| Text does not overlap | Reference designators, values and labels do not overlap each other or sit on wires and symbols; hide the reference designator of the power flag `#FLG` |
| BOM fields | Fill the `LCSC` field (hidden) on mounted parts and verify model and stock on lcsc.com; mark unmounted parts DNP; mounting holes get `in_bom no` |
| Field angle | Interpreted in the symbol's own coordinates: for a symbol rotated 90/270°, the field must be written as 90° to display horizontally; for a symbol rotated 90°/180°, left/right justification must be written the opposite way |

MCP has no batch layout tool, and calling it one by one takes hundreds of calls. You can generate a whole-page layout with a script (keeping all symbol instances and UUIDs, changing only positions and wiring); **after generation the netlist must match the one before the change net by net and pin by pin**, then re-check with `find_overlapping_elements`, `find_wires_crossing_symbols` and local renders.
