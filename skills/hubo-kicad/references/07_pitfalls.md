# 07 Pitfall list

| # | Symptom | Cause | Avoidance |
|---|---|---|---|
| 1 | After sync, DRC shows many shorts, or parity reports `net_conflict` | `sync_schematic_to_board` names nets differently from KiCad and does not update traces or copper pours | Do not use sync; write pad nets from the kicad-cli netlist (03) |
| 2 | After editing one capacitor, GND and +5V are shorted into one net | `batch_connect(replace=true)` does not delete the old global label | Delete the old label first; compare each pin against the netlist afterwards |
| 3 | Hand-entered pin nets are reversed | Manual entry of parameters | Generate the parameters from the wiring table with a script |
| 4 | After routing, the RF traces and power traces are all gone | `import_ses` clears existing copper | Import only into a copy, then merge the new items back (04) |
| 5 | Autorouting runs on the inner ground plane | The DSN exports inner layers as signal | `route_prep.py strip` changes them to power |
| 6 | The exported DSN lacks the newly added keepouts | `export_dsn(boardPath)` used a stale in-memory board; areas that only forbid traces are not exported | `reload_board` first and do not pass boardPath; make keepouts forbid vias as well |
| 7 | After saving, board-edge clearance reverts to 0.5 mm and net classes revert to default | Every MCP save (not only `save_project`) rewrites the design rules in `.kicad_pro` | Put rules in `.kicad_dru`; for things that can only live in `.kicad_pro` (board-level constraints, net classes), write them with a script and rerun it after every MCP save |
| 8 | The user sees full-screen warnings, garbled text and empty notches in the GUI | Only the CLI errors were checked; import leftovers were not cleaned | The GUI review in 06; the leftover list in 02 |
| 9 | Most components have no model in the 3D viewer | PADS does not carry 3D models | Add models and render to check, per 06 |
| 10 | DRC reports zero annular ring on screw holes | The plated holes of the original board have the same diameter as the pad | Enlarge the pad and connect it to ground (mind the clearance to the board edge), and remove the stencil opening |
| 11 | A script changed the file while the user had the GUI open, and the GUI overwrites it on save | Each side holds its own copy | Before editing a file, confirm the GUI has closed this board, or reload it in the GUI afterwards |
| 12 | Objects in a pcbnew script suddenly become untyped `SwigPyObject` | SWIG limitation: after `Remove`, after a second `LoadBoard`, or after loading a board once a library footprint has been loaded | Read and modify everything first, delete at the end; read libraries and boards in separate processes |
| 13 | Changed a 3D model rotation or pad size, but it did not change after saving | `Models()` returns a copy; `GetSize()` returns an internal reference that changes with it | Clear and re-`Add3DModel`; take the values out first, then modify |
| 14 | A field added to a new footprint (such as LCSC) is printed on the silkscreen | A field created by `SetField` is visible by default and on the silkscreen layer | Set it hidden and put it on the Fab layer |
| 15 | The parts library download takes 1.5 GB on the C drive | The path is hard-coded | Do not download; verify on lcsc.com |
| 16 | Freerouting tries to go online to send statistics; or reports `UnsupportedClassVersionError` | Analytics is on by default and uses the system proxy; the Java version is lower than the jar's compile target | Change the config and clear the proxy variables; install the JRE matching the compile target shown by `doctor.py` |
| 17 | Signal vias sit on the inner-plane split gaps of the imported original board | The original design had no constraint | `plane_check.py`; move the signal holes off the split |
| 18 | A newly added GND via creates a roughly 1 mm narrow neck in the power plane | The via anti-pad connects with the split gap | Run `plane_check.py` after placing vias and look at the narrow necks |
| 19 | The inner-plane hole count comes out as 0, wrongly suggesting the plane is intact | Copper pours are stored as "fractured" polygons | `Unfracture` first, then count |
| 20 | After moving the whole board into the drawing frame in the GUI, the freeze comparison, pad check and enclosure coordinates all mismatch | Scripts compare absolute coordinates | "Coordinate origin" in 06 |
| 21 | A schematic wire passes through the middle of a label text | The global label is attached midway along the wire | Draw a short stub and attach the label to it (03) |
| 22 | The enclosure assembly in the 3D export is far off | `pcb export glb` defaults to absolute coordinates | Add `--drill-origin` |
| 23 | Measured differential-pair impedance is off by about 10 Ω | Estimated from a formula, or the default stackup from an EDA / evaluation board file was used | Use the PCB fab's calculator to set width and spacing, per 08 |
| 24 | The JLCPCB international calculator gives a trace width about twice as wide | The first recommended stackup is `JLC04161H-3313A` (two prepreg sheets) | Manually switch to the stackup actually ordered (08, step 3) |
| 25 | After changing width and spacing, DRC passes but the actual traces still have the old size | Only the net class or only the generating script was changed; DRC checks only the lower limit | Change both and run `impedance_check.py` |
| 26 | Intra-pair length mismatch appears out of nowhere, tens of mil | Between two rows of same-net pads of a flow-through ESD part, Freerouting adds a segment overlapping the pre-routed trace, with coordinates off by 100 nm and width larger by 0.1 µm; the dedupe script's strict comparison cannot detect it | Compare both coordinates and width with a 1 µm tolerance when deduping |
| 27 | In 3D, a connector sinks into the board or is shifted back and forth | EasyEDA model offsets are based on the bounding-box center / lowest point, KiCad's on the STEP origin | Convert with `step_bbox.py` (06) |
| 28 | A connector or side-button switch protrudes past the board edge, while DRC passes | DRC does not check the component body; the courtyard is shorter than the real part | `edge_check.py`; correct the courtyard per the datasheet |
| 29 | A custom `.kicad_dru` says "5 mil between traces", yet DRC lets 0.1 mm pass; HDMI/MIPI with a 0.15 net class are also relaxed | KiCad takes the last matching rule in the file for a given constraint type, and custom rules take precedence over net classes: an unconditional broad clearance rule written later overrides earlier specific rules and the net classes | Put broad rules first and specific rules after; limit clearance rules to copper whose two sides are both in the Default net class (`assets/jlc_base.kicad_dru` already fixed); after changing, rerun `power_rules.py` to sync the project |
| 30 | Ground copper poured beside a differential pair; DRC and `hs_review` pass, yet eye-diagram crosstalk gets worse | The guard copper is grounded by vias only at the two ends (or not at all), so the long strip of copper becomes a resonant cavity; most common when the pour fills the narrow gap between traces | `fence_check.py` checks the ground via spacing along the line (SPEC-005 2.9); delete strips too narrow for vias and leave 3W spacing instead |
| 31 | Calling a script under Git Bash, an argument like `/LORA_` becomes `C:/Program Files/Git/LORA_` | MSYS rewrites arguments starting with `/` as POSIX paths | Prefix the command with `MSYS_NO_PATHCONV=1`; `prod_gate` reads its arguments from json and is not affected |
| 32 | Freerouting reports hundreds of violations, or routes around regions that should not be keepouts | `export_dsn` exports rule areas that are only descriptive (forbidding nothing) as two-layer keepouts, and the outer-layer GND pour as a whole-board conductor on the signal layers | Delete these rule areas / pours in the routing copy before exporting |
| 33 | Freerouting routes next to a pad such as an antenna feed pin, and DRC reports a clearance error | `export_dsn` does not export pad-local clearances | In the routing copy, add a two-layer keepout (traces + vias) around that pad |
| 34 | Vias from `add_gnd_stitching_vias` land in GND pads, in rule-area keepouts, or on board-edge rounded corners | It picks points on a grid only, without checking rule areas, via spacing, or same-net pads | After placing, delete the violating vias according to the DRC result, then check via-in-pad in `route_check` |
| 35 | An evaluation-board intra-pair length mismatch is taken as the spec (for example the EVB MIPI "about 630 mil"), or HDMI inputs are assumed to need AC coupling capacitors | Evaluation-board values cannot be used as a spec (numbers read by skimming disagree with a full parse); the HDMI input side is biased by the source, with no coupling capacitor | Take values from the chip vendor's spec and the body of SPEC-005; use the evaluation board only as a reference, and fully parse it before citing |
| 36 | Inter-pair length mismatch looks large from the trace length, but is actually compensated by layer-change vias | Total trace length excludes the via barrel | Item 13 of `hs_review` already counts layer-change vias (one board thickness per via) |
| 37 | JLCPCB adds a surcharge on the order, and the review reply says "via inner diameter < 0.3, outer diameter ≤ 0.4" | The via rule's lower limit was set to a 0.2 mm hole, and the board has 0.2/0.4 and 0.25/0.45 vias | Via hole ≥ 0.3 mm and outer diameter ≥ 0.45 mm (SPEC-005 10.4; `jlc_base.kicad_dru` already fixed); run `prod_gate.py` before export |

## Usage notes

- `find_component(reference="R1")` is a **substring match** and also returns R10-R19;
- The `netName` of `get_net_connections` must be the name **without a hierarchy prefix** (passing `/VPP_ON` returns empty);
- `register_*_library` writes absolute paths; change them to `${KIPRJMOD}` afterwards with `set_library_table_uri`;
- `create_project` also generates an empty `.kicad_pcb` and loads it as the current board;
- Python patches containing regex backslashes or Chinese anchors are error-prone in a Git Bash heredoc; write the patch script to a file and run it with `python -X utf8`.
