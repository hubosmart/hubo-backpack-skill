## Summary

A six-stage (0–5), gate-checked workflow for taking a board from schematic to production files in KiCad 10:
environment check (`scripts/doctor.py`), optional import from EasyEDA Pro, verification, schematic,
PCB and routing, review, and export. Each stage has a reference file under `references/` and a
completion criterion; read the reference before starting the stage.
KiCad is the primary tool; to work inside EasyEDA (JLCPCB), use the official easyeda-api-skill
(see the repository README).
Production files are only exported through `scripts/export_prod.py`, which always runs the production
gate `scripts/prod_gate.py` (DRC, routing rules, impedance, planes, fences); do not bypass it.
Run all scripts with KiCad's bundled python. Self-test: `tests/run_all.py` ends with `ALL PASS`.
Original EasyEDA projects are read-only; Freerouting results are merged into a copy only.

## What to do

Work stage by stage. Before each stage, read the matching `references/` file, and move on only when the "completion criterion" is met.

| Stage | Read | Completion criterion |
|---|---|---|
| 0 Environment | `references/01_environment_setup.md`; run `scripts/doctor.py` first | All required doctor items pass; `claude mcp get kicad` shows Connected |
| 1 Conversion | `references/02_easyeda_import_and_verification.md` | Original is read-only and its sha256 recorded; the 5 classes of PADS-import defects fixed and import leftovers cleaned |
| 2 Verification | Same file, "Verification after conversion" | Pad nets, copper geometry, board outline, RF zone and per-pad positions are each checked against an independent source; baseline snapshot of the frozen parts built |
| 3 Schematic | `references/03_schematic.md` | ERC 0; netlist matches the wiring table pin by pin; no overlap or lines crossing text in the layout |
| 4 PCB / routing | `references/04_pcb_and_routing.md`, `references/05_plane_splits_and_stitching_vias.md`; with RF / high-speed differential / USB, read `references/08_impedance_control.md` first; before placement read `references/09_routing_rules.md` (write `<board>.hz_layout.json`, generate DRC rules with `power_rules.py`, set signal grades) | DRC 0 errors / 0 warnings / 0 unconnected; parity 0; freeze comparison passes; `plane_check.py` has no FAIL; with impedance traces, `impedance_check.py` has no FAIL; `route_check.py` has no line marked "NOT MET"; with signals above grade L, `hs_review.py` has no "NOT MET"; for high-speed differential pairs with guard-ground copper, `fence_check.py` has no "NOT MET" |
| 5 Review, export, order | `references/06_review_export_and_order.md` | UI review and 3D check done; `export_prod.py` production gate passes (or is waived with the user's consent) and all outputs exist; BOM part numbers checked on lcsc.com; surcharges on the order page confirmed per "Pre-order checks" in 06 |

On any anomaly, check `references/07_pitfalls.md` first. To operate on a project inside EasyEDA, use the official easyeda-api-skill (see the repository README); that is outside this skill.

## Hard rules (each one maps to a real loss)

1. **The original EasyEDA project is read-only**: copy it to a new project directory first, and do all unpacking, exporting and editing on the copy.
2. **Generate MCP parameters from data**: pin nets, coordinates and the like are generated by script from the wiring table / data file, never typed by hand; after every change, check the netlist pin by pin.
3. **Do not use `sync_schematic_to_board`**: write pad nets from the kicad-cli netlist; parity must be 0.
4. **Import Freerouting results into a copy only**: `import_ses` wipes existing copper; merge only the new tracks/vias (`route_prep.py merge`).
5. **Before changing files, make sure the KiCad UI does not have this board open**; after a script or kicad-cli has modified the board file, run `reload_board` before using MCP again.
6. **0 errors does not mean ready to order**: the target is 0 errors and 0 warnings, plus a look through the KiCad UI.
7. **MCP first, and record the gaps**: when you switch to a script, state why MCP could not do it.
8. Conclusions need evidence: read datasheets from the original drawings, verify part numbers on lcsc.com, compare geometry against the production Gerber; if no evidence can be found, say "unverified".
9. **Impedance trace width/spacing come only from the PCB fab's calculator**: before starting, ask the user which platform will make the PCB and which stackup; do not assume or estimate; recompute at the verification points for every project (08).
10. **Do not bypass the production gate**: `export_prod.py` always runs `prod_gate.py` before exporting; if it fails, fix the board. Use `--allow` only with the user's explicit consent, and write down who agreed (06). Use only `export_prod.py` to produce files for the manufacturer; the MCP export tools (`export_gerbers`, `export_drill`, `export_pos`, `export_bom`, etc.) skip the gate and are for viewing only.

## Scripts (always run with KiCad's bundled python)

| Script | Purpose |
|---|---|
| `scripts/doctor.py` | Environment self-check: pcbnew, kicad-cli, library table initialization, shapely, kicad MCP, Java and Freerouting (Java version checked against the jar's compile target) |
| `scripts/route_prep.py` | Freerouting pre/post-processing: `copy` the routing copy and keepouts, `strip` DSN post-processing, `dump` / `merge` merging only new items |
| `scripts/plane_check.py` | Inner-plane split line width, holes crossing split lines (signal/GND), narrow necks in power planes |
| `scripts/set_origin.py` | Set the drill/coordinate origin (board center or given coordinates) |
| `scripts/export_prod.py` | JLCPCB order files: Gerber + drill zip, BOM, KiCad position file and JLCPCB CPL; always passes the production gate before exporting |
| `scripts/prod_gate.py` | Production gate: project configuration, DRC rule consistency, DRC, `route_check` and the high-speed / impedance / plane / guard-ground via checks from the configuration; refuses to export on failure (06) |
| `scripts/power_rules.py` | Writes the base rule template and the minimum power-net widths into the project `.kicad_dru` according to `<board>.hz_layout.json` (09) |
| `scripts/impedance_check.py` | Compares actual differential trace width and intra-pair spacing with the specified values; checks the length of necked-down sections in the breakout area |
| `scripts/stackup.py` | Writes the KiCad stackup (layer thickness, Dk), copper layer display names (SPEC-003 6.1.1), off-board impedance notes and stackup notes according to `assets/impedance_table.json` |
| `scripts/route_check.py` | Basic routing check (all nets): right angles / acute angles / acute-angle slivers, via-in-pad (grounding vias in thermal pads are allowed under the 10.7 exception) (09); trace width/spacing and power widths are left to DRC |
| `scripts/miter.py` | Automatically turns corners > 45° into 45° bends, verifying each with DRC and reverting on conflict (09) |
| `scripts/hs_review.py` | Geometric review of high-speed traces: corners, ground vias beside layer-change vias, copper-pour setback, aggressor distance, GND pour between pairs, reference plane, differential via count, intra-pair length difference, test points, no-via nets, crystal-to-clock-pin distance (09) |
| `scripts/fence_check.py` | Guard-ground vias for high-speed differential pairs: via spacing along the guard copper (MIPI 3, HDMI 4, USB 2.0 6 mm), and guard copper grounded only at its ends (09 section 3.1) |
| `scripts/dedupe.py`, `scripts/mini_route.py`, `scripts/island_via.py` | After the Freerouting merge: deduplication, A* fill-in routing, ground vias for GND islands (04) |
| `scripts/model_audit.py`, `scripts/step_bbox.py`, `scripts/edge_check.py` | 3D model file audit, EasyEDA model offset conversion, check for parts protruding past the board edge (06) |

When calling from Git Bash, prefix the command with `MSYS_NO_PATHCONV=1`, otherwise arguments such as `/LORA_` get rewritten into paths (07 item 31).
Self-test: `"<KiCad install dir>/bin/python.exe" tests/run_all.py`; the last line should be `ALL PASS`.

## Why it is designed this way

- **Stages are split out and details live in references**: the full SOP is long, and reading it all at once would crowd the context; each stage reads one file, and the completion criteria in the table stop the flow from advancing just because "the tool returned success".
- **Scripts hold only what is independent of a specific board**: module keepout names, plane layers and nets to clear are all parameters. Checks bound to one board (frozen parts at fixed coordinates, the impedance baseline of a particular RF net) stay in that project's repository.
- **Impedance values are maintained in one place only, the spec**: SPEC-003 6.5 (in the hubo-backpack-spec repository, https://github.com/hubosmart/hubo-backpack-spec) is the single source, and `assets/impedance_table.json` is its versioned machine-readable copy. Stackup model names stay the same while the fab updates the parameters, so every project rechecks the verification points instead of hard-coding the values into the flow.
- **The Freerouting Java version is read from the jar**: 2.0.x needs Java 21 and versions after 2.2.2 need 25; hard-coding a version makes the check useless (measured: 2.4.1 under Java 21 fails every run with `UnsupportedClassVersionError`).
- **Checks are enforced at the exit**: the stage table and hard rules are requirements written for the agent and can be skipped; `export_prod.py` is the only exit for production files and calls `prod_gate.py` there, so a failing board cannot be exported whether or not the earlier checks were run. The requirements exist as data in `<board>.hz_layout.json`, and the scripts judge from it rather than from the agent's memory.
- **Production-file coordinates follow the drill origin**: when the board is translated as a whole in the UI, all absolute coordinates change; exporting relative to the origin keeps the BOM and position files byte-identical before and after the translation.
- **Order conditions record only the trigger conditions and where to check, not prices**: prices and order rules change at any time (in 2026-08 JLCPCB's free HASL prototype coupons were replaced by OSP), and hard-coding them would turn stale information into evidence. Process values are maintained only in SPEC-005 (general PCB layout spec); 06 only cites clauses, and the price calculator is authoritative at submission time.

## What this skill does not do (boundaries)

- It does not replace circuit design judgment: component selection, matching network values and power budget are decided by the designer; this skill only guarantees process and checking.
- It does not modify the original EasyEDA project, and does not export a KiCad project back to EasyEDA (EasyEDA can only import the KiCad 5.x format, so migration is one-way).
- It does not handle 3D enclosure design; it only reminds you to add `--drill-origin` when exporting GLB.
- It does not push code or place orders on your behalf.
